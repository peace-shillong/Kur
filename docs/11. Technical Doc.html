Executive Summary

The Kur Web App is a high-performance genealogical and cultural preservation platform dedicated to Khasi clan kinship (Tipkur Tipkha) and traditional marriage exogamy verification (Bishar ia ka Sang).

To maintain lightweight initial bundle delivery, achieve sub-2ms responsiveness on mobile devices, ensure complete offline functionality in Meghalaya, and avoid costly upstream rate limits (HTTP 429), the application employs a streamlined Cascading Pipeline:

Device Cache (LocalStorage) → Compressed JSON Asset (/assets/*.json) → Local API (Cloudflare Worker + D1) → Upstream Tynrai-AI API

Rather than bundling hundreds of historical clan records into the main JavaScript bundle (which inflated bundle sizes beyond 1 MB), datasets are externalized into compressed, minified JSON assets under /assets/ (commonSurnames.json and clanList.json). Each JSON asset contains explicit metadata honoring and crediting the two foundational historical sources:

  • Rev. I. Kharkongngor (2004) — Ka Jymbriew Bad Ka Thymmei Longkur Longjait U Khasi
  • Babu Spiton Kharakor (1981) — Ki Khun Ki Ksiew U Hynñiew Trep
ⓘ
Two Primary Operational Modes: 1. mode: "wad-kur" — Clan genealogy, returning origin, sub-clans (kpoh_clans), sister clans (shikur_clans), and covenant pacts (teh_kur_clans).
2. mode: "bishar-sang" — Pairwise exogamy evaluation between two surnames, evaluating direct bloodlines, maternal sister clans, and localized covenant prohibitions.

System Architecture & Data Pipeline

Every query initiates at the edge client and waterfalls sequentially down the hierarchy. If any tier satisfies the query, execution terminates immediately, short-circuiting all subsequent network calls.

Before dispatching any network fetch, the client immediately checks window.localStorage. Any surname genealogy (Wad-Kur) or pairwise marriage verdict (Bishar-Sang) evaluated previously on that phone or computer resolves in under 2ms with zero network consumption.

Asynchronous Asset Resolution Algorithm

import { TipkurResponse } from '../types';

let cachedCommonData: Record<string, TipkurResponse> | null = null;

export async function getCommonSurnameResponse(jait: string): Promise<TipkurResponse | undefined> {
  if (!jait) return undefined;
  
  // 1. Check in-memory variable
  if (!cachedCommonData) {
    const res = await fetch('/assets/commonSurnames.json');
    const json = await res.json();
    cachedCommonData = json.data;
  }

  const clean = jait.trim();
  const norm = normalizeKhasi(clean);

  return cachedCommonData[clean.toLowerCase()] || cachedCommonData[norm];
}

Step 3: Local API Endpoint & Cloudflare D1

When client-side caches miss, the frontend dispatches a POST request to the local API endpoint (e.g., https://kur-api.kyrshan.com/api/wad-kur or /api/bishar-sang), powered by a Cloudflare Worker connected to a Cloudflare D1 SQL Database.

⚡
Edge D1 Lookup (Regional Edge Caching): Before invoking Tynrai-AI, the Worker executes an ultra-fast SQLite query on Cloudflare D1. If another user in the world previously queried this surname or pair, D1 returns the saved response in ~40ms!

1. Frontend Client Cascading Orchestrator (TypeScript)

/**
 * src/services/api.ts
 * Cascading retrieval: Device Cache → JSON Asset → Local API (D1) → Tynrai Upstream
 */
import { TipkurResponse } from '../types';
import { getCommonSurnameResponse } from '../data/commonSurnames';
import { getDeviceCachedWadKur, saveDeviceCachedWadKur } from '../utils/deviceCache';

export async function searchClanApi(jait: string): Promise<TipkurResponse> {
  const clean = jait.trim();

  // STEP 1: Device Cache (LocalStorage — <2ms)
  const deviceCached = getDeviceCachedWadKur(clean);
  if (deviceCached) {
    return deviceCached;
  }

  // STEP 2: Compressed JSON Asset (/assets/commonSurnames.json — 5-15ms)
  // Sourced from Rev. I. Kharkongngor (2004) & Babu Spiton Kharakor (1981)
  const assetResponse = await getCommonSurnameResponse(clean);
  if (assetResponse) {
    saveDeviceCachedWadKur(clean, assetResponse); // Hydrate device cache
    return assetResponse;
  }

  // STEP 3 & 4: Local API (Cloudflare Worker + D1 SQL) & Upstream Tynrai-AI
  const config = getStoredApiConfig();
  const response = await fetch(config.baseUrl, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ mode: 'wad-kur', jait: clean })
  });

  if (!response.ok) {
    throw new Error(`Server returned ${response.status}`);
  }

  const data: TipkurResponse = await response.json();

  // STEP 6: Save to Device LocalStorage and return
  saveDeviceCachedWadKur(clean, data);
  return data;
}

2. Cloudflare Worker Edge Handler (Tier 4 & 5 with D1 Write-Back)

/**
 * Cloudflare Worker: /api/wad-kur
 * Environment bindings:
 * - env.DB: Cloudflare D1 Database
 * - env.TYNRAI_API_URL: https://tynrai.in/.netlify/functions/tipkur-api
 * - env.TYNRAI_API_KEY: Bearer token
 */
export default {
  async fetch(request, env, ctx) {
    if (request.method !== 'POST') {
      return new Response('Method Not Allowed', { status: 405 });
    }

    const { jait } = await request.json();
    const clean = jait ? jait.trim() : '';
    const norm = normalizeKhasi(clean);

    // 1. Check Cloudflare D1 Edge SQLite Database
    const existing = await env.DB.prepare(
      'SELECT response_json FROM clans_cache WHERE normalized_jait = ?'
    ).bind(norm).first();

    if (existing && existing.response_json) {
      return new Response(existing.response_json, {
        headers: { 'Content-Type': 'application/json', 'X-Cache-Status': 'HIT-D1' }
      });
    }

    // 2. D1 Cache Miss: Invoke Tynrai-AI Upstream with Bearer Auth
    const upstreamResp = await fetch(env.TYNRAI_API_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${env.TYNRAI_API_KEY}`
      },
      body: JSON.stringify({ mode: 'wad-kur', jait: clean })
    });

    if (!upstreamResp.ok) {
      return new Response(upstreamResp.body, { status: upstreamResp.status });
    }

    const responseData = await upstreamResp.json();
    const jsonString = JSON.stringify(responseData);

    // 3. Asynchronously write-back to D1 without blocking client response
    ctx.waitUntil(
      env.DB.prepare(`
        INSERT OR REPLACE INTO clans_cache (normalized_jait, original_jait, response_json, citation)
        VALUES (?, ?, ?, ?)
      `).bind(
        norm,
        clean,
        jsonString,
        responseData.clusters?.[0]?.citation || 'Tynrai-AI Knowledge Graph'
      ).run()
    );

    return new Response(jsonString, {
      headers: { 'Content-Type': 'application/json', 'X-Cache-Status': 'MISS-D1-WRITTEN' }
    });
  }
};
