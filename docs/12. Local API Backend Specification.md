## 1. Executive Summary & System Objectives

The **Kur Local API** acts as a regional high-speed edge middleware between the **Kur Web App** (Frontend PWA) and the upstream **Tynrai-AI inference server**.

### Key System Responsibilities
1. **Edge Caching & Low Latency**: Utilize Cloudflare D1 (edge SQLite) to serve previously queried surnames and marriage checks in **30–80ms**, eliminating redundant network calls to Tynrai-AI.
2. **Zero-Client Secret Isolation**: Maintain all upstream credentials (`TYNRAI_API_KEY`, Netlify function endpoints, database tokens) exclusively in Cloudflare Worker environment bindings. The frontend client has zero secrets.
3. **Smart Community Submissions**:
   - Provide a real-time pre-check endpoint (`GET /api/check-clan-status`). If a user's clan already exists in `clans_master` or `clans_cache`, the user is not forced to fill the lengthy 6-field "Ai Jingtip" form. Instead, they can submit a 1-click **Inclusion Request**.
   - If the clan does not exist, the user submits the full **Ai Jingtip** form.
4. **Resilient Upstream Delivery**:
   - Forward valid "Ai Jingtip" submissions to Tynrai-AI.
   - If Tynrai-AI returns `200 OK`, confirm success to the user and mark synced in D1.
   - If Tynrai-AI returns an error (500, 502, 429) or times out, save the submission to D1 locally and instruct the user to email the details to `dkhar@kyrshan.com` as outlined in `6. Frontend Checklist.md`.
5. **Grievance / Dispute Management ("Ujor Jingbakla")**:
   - Accept and record community reports of incorrect clan affiliations (*shikur* vs *teh kur* errors), storing them in D1 for genealogical review by clan elders (*Rangbah Kur* / *Seng Kur*).

> **Instructions for Developer / AI Agent:**  
> Use the prompt below to generate or bootstrap the Cloudflare Worker backend project for the Kur Local API.

```markdown
# Role & Goal
You are an expert Backend Systems Architect specializing in Cloudflare Workers, Hono, and Cloudflare D1 (SQLite). Your task is to build the production Local Backend API for "Kur Tipkur" (a Khasi clan genealogical web application).

# Technology Stack
- Runtime: Cloudflare Workers (ES modules)
- Framework: Hono (v4.x)
- Database: Cloudflare D1 (SQLite)
- Language: TypeScript (strict mode)
- Validation: Zod or lightweight manual sanitization
- Upstream Target: Tynrai-AI API (https://tynrai.in/.netlify/functions/tipkur-api)

# Project Requirements & Features
1. CORS & Security:
   - Allow requests from origin: 'https://kur.kyrshan.com', 'http://localhost:5173', 'http://localhost:4173'
   - Include OWASP-recommended security headers (X-Content-Type-Options, Strict-Transport-Security, X-Frame-Options)
   - Zero secrets exposed to client: Upstream TYNRAI_API_KEY must be stored via wrangler secret put

2. Clan Normalization Utility:
   - Provide a clean normalizeKhasi(str) function that strips diacritics (ï/Ï -> i, ñ/Ñ -> n), converts to lowercase, and strips extra whitespace and punctuation for canonical key lookups.

3. Database Schemas (Cloudflare D1):
   - clans_master: Master list of 516 clans
   - clans_cache: Caches wad-kur queries (normalized_jait, raw_jait, response_json, citation)
   - bishar_sang_cache: Caches bishar-sang evaluations (pair_key, jait_a, jait_b, verdict, can_marry, response_json)
   - ujor_reports: Grievance/correction reports on clan kinship (clan_name, related_clan, mistake_type, description, reporter_name, reporter_contact, status)
   - ai_jingtip_submissions: User-submitted clan lineages (jait, full_name, email, shikur_clans, teh_kur_clans, notes, tynrai_sync_status, tynrai_status_code)
   - clan_inclusion_requests: Lightweight requests when a clan already exists (jait, matched_clan_id, requester_name, contact)

4. Endpoints to Implement:
   - GET /api/health -> Returns 200 with timestamp and D1 connection status
   - GET /api/clans -> Returns list of clans from clans_master (supports ?q= query and ?limit=)
   - POST /api/wad-kur -> 
     1. Check D1 clans_cache. If hit, return cached response with header X-Cache-Status: HIT-D1.
     2. If miss, call Tynrai-AI with Bearer token.
     3. Save successful Tynrai-AI response to D1 via ctx.waitUntil() and return with X-Cache-Status: MISS-D1-FETCHED.
   - POST /api/bishar-sang ->
     1. Sort [jait_a, jait_b] alphabetically to generate pair_key = norm(a) + "__" + norm(b).
     2. If jait_a === jait_b, immediately return SANG_PROHIBITED verdict.
     3. Check D1 bishar_sang_cache. If hit, return.
     4. If miss, call Tynrai-AI, save to D1, and return.
   - GET /api/check-clan-status?jait=:name ->
     - Check clans_master and clans_cache for the normalized clan name.
     - If found: return { exists: true, matched_clan: string, message: "Clan exists. Use simple inclusion form." }
     - If not found: return { exists: false, message: "Clan does not exist. Please submit full Ai Jingtip form." }
   - POST /api/clan-inclusion ->
     - Insert into clan_inclusion_requests. Return success confirmation.
   - POST /api/ai-jingtip ->
     - Validate fields. Save submission to D1 ai_jingtip_submissions.
     - Forward payload to Tynrai-AI upstream API.
     - If Tynrai returns 200: Update D1 status to 'synced' and return { success: true, message: "La pdiang ia ka jingtip!" }
     - If Tynrai returns non-200 or fails: Update D1 status to 'failed' and return { success: false, fallback_required: true, email: "dkhar@kyrshan.com", message: "Error syncing with Tynrai. Please email details to dkhar@kyrshan.com" }
   - POST /api/ujor ->
     - Validate fields (description min 10 chars). Save into ujor_reports. Return 201 Created.

5. Deliverables:
   - wrangler.toml configuration
   - schema.sql D1 migrations
   - Full TypeScript source code using Hono (src/index.ts, src/types.ts, src/db.ts)
   - Seed script to load initial clans from assets/clanList.json
```

## 4. Cloudflare D1 SQL Database Schema & Indices

Create file `schema.sql` inside the Cloudflare Worker repository:

```sql
-- ====================================================================
-- KUR LOCAL API - CLOUDFLARE D1 DATABASE SCHEMA
-- Migration: 0001_initial_schema.sql
-- ====================================================================

-- 1. MASTER CLAN DIRECTORY (516 Historical & Verified Clans)
CREATE TABLE IF NOT EXISTS clans_master (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  normalized_name TEXT UNIQUE NOT NULL,      -- e.g. "kharkongor", "diengdoh"
  display_name TEXT NOT NULL,                 -- e.g. "Kharkongor", "Diengdoh"
  kur_cluster_id TEXT,                        -- Grouping / Kur family identifier
  aliases_json TEXT DEFAULT '[]',             -- Alternative spellings/sub-branches
  is_common INTEGER DEFAULT 0,                -- 1 for top 26 common surnames
  source TEXT DEFAULT 'kharkongngor-2004',    -- Citation source
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_clans_master_norm ON clans_master(normalized_name);
CREATE INDEX IF NOT EXISTS idx_clans_master_common ON clans_master(is_common);


-- 2. WAD-KUR QUERY CACHE (Clan Genealogy & Kinship Clusters)
CREATE TABLE IF NOT EXISTS clans_cache (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  normalized_jait TEXT UNIQUE NOT NULL,       -- Normalized search query
  original_jait TEXT NOT NULL,                -- User's raw query string
  response_json TEXT NOT NULL,                -- Full TipkurResponse JSON
  citation TEXT,                              -- Primary literature citation
  cluster_count INTEGER DEFAULT 1,
  source TEXT DEFAULT 'tynrai-ai',            -- 'seed-asset' | 'tynrai-ai' | 'curated'
  hit_count INTEGER DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_clans_cache_norm ON clans_cache(normalized_jait);


-- 3. BISHAR-SANG CACHE (Pairwise Exogamy Evaluations)
CREATE TABLE IF NOT EXISTS bishar_sang_cache (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pair_key TEXT UNIQUE NOT NULL,              -- Symmetrically sorted: "clan_a__clan_b"
  jait_a TEXT NOT NULL,
  jait_b TEXT NOT NULL,
  verdict TEXT NOT NULL,                      -- 'SANG_PROHIBITED' | 'DISTINCT_CLANS' | 'UNMAPPED_VERIFY_KINSHIP'
  can_marry INTEGER NOT NULL,                 -- 0 (Forbidden) or 1 (Permitted)
  reason_khasi TEXT,
  reason_english TEXT,
  citation TEXT,
  response_json TEXT NOT NULL,                -- Full BisharSangResponse JSON
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_bishar_sang_pair ON bishar_sang_cache(pair_key);


-- 4. UJOR REPORTS (Grievance & Kinship Mistake Submissions)
CREATE TABLE IF NOT EXISTS ujor_reports (
  id TEXT PRIMARY KEY,                        -- e.g. "ujor-1732728900-a1b2"
  clan_name TEXT NOT NULL,                    -- Clan with suspected error
  related_clan TEXT,                          -- Incorrectly linked clan
  mistake_type TEXT NOT NULL,                 -- 'shikur_wrong' | 'tehkur_wrong' | 'spelling' | 'other'
  description TEXT NOT NULL,                  -- Detailed explanation (min 10 chars)
  reporter_name TEXT,                         -- Optional user name
  reporter_contact TEXT,                      -- Email or phone number
  ip_hash TEXT,                               -- Anonymized SHA-256 IP hash for abuse prevention
  status TEXT DEFAULT 'pending',              -- 'pending' | 'under_review' | 'resolved' | 'dismissed'
  admin_notes TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_ujor_status ON ujor_reports(status);
CREATE INDEX IF NOT EXISTS idx_ujor_clan ON ujor_reports(clan_name);


-- 5. AI JINGTIP SUBMISSIONS (Community Clan Lineage Contributions)
CREATE TABLE IF NOT EXISTS ai_jingtip_submissions (
  id TEXT PRIMARY KEY,                        -- e.g. "jingtip-1732728900-xyz"
  jait TEXT NOT NULL,                         -- Primary surname being submitted
  normalized_jait TEXT NOT NULL,
  full_name TEXT,                             -- Submitter's name
  email TEXT,                                 -- Submitter's email
  shikur_clans TEXT,                          -- Comma/text separated sister clans
  teh_kur_clans TEXT,                         -- Comma/text separated covenant clans
  notes TEXT,                                 -- Oral history or village details
  tynrai_sync_status TEXT DEFAULT 'pending',  -- 'synced' | 'failed' | 'pending'
  tynrai_status_code INTEGER,                 -- HTTP status received from Tynrai-AI
  tynrai_error_msg TEXT,                      -- Error message if failed
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_jingtip_norm ON ai_jingtip_submissions(normalized_jait);
CREATE INDEX IF NOT EXISTS idx_jingtip_sync ON ai_jingtip_submissions(tynrai_sync_status);


-- 6. CLAN INCLUSION REQUESTS (Simplified 1-Click Submissions for Existing Clans)
CREATE TABLE IF NOT EXISTS clan_inclusion_requests (
  id TEXT PRIMARY KEY,                        -- e.g. "inc-1732728900-k7"
  jait TEXT NOT NULL,                         -- Requested surname
  normalized_jait TEXT NOT NULL,
  matched_master_name TEXT NOT NULL,          -- Matched record in clans_master/cache
  requester_name TEXT,
  requester_contact TEXT,
  notes TEXT,
  status TEXT DEFAULT 'pending',              -- 'pending' | 'approved' | 'merged'
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_inclusion_norm ON clan_inclusion_requests(normalized_jait);
```

## 5. API Communication Contract & Endpoint Specifications

### Common HTTP Headers
- **Response Headers**:
  - `Content-Type: application/json; charset=utf-8`
  - `X-Cache-Status`: `HIT-D1` | `MISS-D1-FETCHED-TYNRAI` | `LOCAL-ASSET-MATCH`
  - `Access-Control-Allow-Origin`: `https://kur.kyrshan.com`
  - `Cache-Control`: `public, max-age=3600, s-maxage=86400, stale-while-revalidate=604800` (for read queries)

## 7. Tynrai-AI Upstream Integration & Resilience (HTTP 200 vs Fallback)

### Outbound Gateway Configuration
Inside the Cloudflare Worker, forwarding to Tynrai-AI uses native `fetch`:

```typescript
// Upstream Forwarder Routine in Cloudflare Worker
async function forwardToTynrai(
  payload: Record<string, unknown>,
  env: Env,
  ctx: ExecutionContext
): Promise<{ ok: boolean; status: number; data?: any; error?: string }> {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 6500); // 6.5s timeout

  try {
    const upstreamResp = await fetch(env.TYNRAI_API_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${env.TYNRAI_API_KEY}`,
        'User-Agent': 'Kur-Local-API/1.0 (+https://kur.kyrshan.com)'
      },
      body: JSON.stringify(payload),
      signal: controller.signal
    });

    clearTimeout(timeoutId);

    if (upstreamResp.ok) {
      const data = await upstreamResp.json();
      return { ok: true, status: upstreamResp.status, data };
    }

    const errText = await upstreamResp.text().catch(() => 'Upstream error');
    return { ok: false, status: upstreamResp.status, error: errText };
  } catch (err: any) {
    clearTimeout(timeoutId);
    return {
      ok: false,
      status: err.name === 'AbortError' ? 504 : 502,
      error: err.message || 'Network gateway failure'
    };
  }
}
```

### Fallback Policy
1. If status is `200`: Return standard positive JSON response.
2. If status is non-200 (e.g. 429, 500, 502, 504):
   - The submission is **not discarded**. It is safely persisted in the Worker's local D1 SQLite table `ai_jingtip_submissions` with `tynrai_sync_status = 'failed'`.
   - The response includes `fallback_required: true` and `fallback_email: "dkhar@kyrshan.com"`.
   - The client UI surfaces an alert banner with a one-click `mailto:dkhar@kyrshan.com?subject=Ai%20Jingtip%20Submission` pre-filled link.

## 8. Security Architecture & Secrets Management

### Strict Isolation Rules
- **No Secrets in Client App**: The frontend build produced by Vite contains **zero** Tynrai API keys, database credentials, or private tokens.
- **Environment Bindings**:
  - `wrangler.toml` holds non-sensitive variables and custom domain routes:
    ```toml
    name = "kur-local-api"
    main = "src/index.ts"
    compatibility_date = "2024-11-01"
    routes = [
      { pattern = "kur-api.kyrshan.com/*", zone_name = "kyrshan.com" }
    ]

    [vars]
    ENVIRONMENT = "production"
    LOCAL_API_HOST = "https://kur-api.kyrshan.com"
    TYNRAI_API_URL = "https://tynrai.in/.netlify/functions/tipkur-api"
    FALLBACK_CONTACT_EMAIL = "dkhar@kyrshan.com"
    ALLOWED_ORIGINS = "https://kur.kyrshan.com,http://localhost:5173"

    [[d1_databases]]
    binding = "DB"
    database_name = "kur-d1-prod"
    database_id = "<YOUR_D1_DATABASE_ID>"
    ```
- **Encrypted Secrets via Wrangler CLI**:
  ```bash
  # Securely inject API secret into Cloudflare Worker without saving in Git
  npx wrangler secret put TYNRAI_API_KEY
  # (When prompted, paste the secret key)
  
  # Optional: Secret key for admin tasks
  npx wrangler secret put ADMIN_API_KEY
  ```

### Input Validation & Sanitization
All incoming strings are strictly sanitized before SQL parameter binding:
- Max string lengths: Surname (`60` chars), Names (`120` chars), Descriptions (`1000` chars).
- Control characters and HTML tags are stripped.
- All D1 queries utilize parameterized statements (`env.DB.prepare(...).bind(...)`) preventing SQL injection.

## 10. Frontend Client Integration (`src/services/api.ts`)

To integrate the frontend application with the Local API, `src/services/api.ts` connects through the tiered cascade:

```typescript
/**
 * Frontend API Gateway Service: src/services/api.ts
 */
const LOCAL_API_BASE = import.meta.env.VITE_LOCAL_API_URL || 'https://kur-api.kyrshan.com/api';

// 1. Submit Clan Mistake Report (Ujor)
export async function submitClanMistakeReport(report: {
  clanName: string;
  relatedClan: string;
  mistakeType: string;
  description: string;
  reporterName: string;
  reporterContact: string;
}): Promise<{ success: boolean; message: string }> {
  const resp = await fetch(`${LOCAL_API_BASE}/ujor`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      clan_name: report.clanName,
      related_clan: report.relatedClan,
      mistake_type: report.mistakeType,
      description: report.description,
      reporter_name: report.reporterName,
      reporter_contact: report.reporterContact
    })
  });
  return await resp.json();
}

// 2. Pre-check Clan Status for Ai Jingtip
export async function checkClanStatus(jait: string): Promise<{
  exists: boolean;
  matched_name?: string;
  action: 'simplified_inclusion' | 'full_ai_jingtip';
  message_khasi: string;
  message_english: string;
}> {
  const clean = encodeURIComponent(jait.trim());
  const resp = await fetch(`${LOCAL_API_BASE}/check-clan-status?jait=${clean}`);
  return await resp.json();
}

export async function submitAiJingtip(payload: {

      teh_kur_clans: payload.tehKurClans,
```
